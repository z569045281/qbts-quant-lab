## 🎯 决策仪表盘 `/` —— 驾驶舱 + 5 标签页(2026-07-29 重排)

用户原话:「太复杂了,复杂到我已经看不明白了,layout 也不直观」。查下来**毛病不是
信息量,是没有层级** —— 改之前 21 个顶层区块全是同一种白卡片、同一个圆角阴影、
同一号标题,SMC 那 700 行和「今日行动」长得一样重,视觉重量没有编码重要性,
大脑就没法排序。整页约 8000px。

**北极星**(CLAUDE.md 一句话定义):这个页面只回答**今天买 QBTX / 买 QBTZ / 观望,
以及怎么下单**。凡是不服务这一句的,一律降级。

### 首屏 = 驾驶舱(1440×900 笔电不用滚)

```
[警报槽]      ← 计划失效 / 决策过期 / 判断不稳定 / 事件日熔断;不出事时零像素
[价格轨]      ← QBTS 大字 + 涨跌 + session 徽章 + QBTX/QBTZ + 数据时效
[裁决 | 交易计划 | 四条军规]   ← 三栏宽度不等是刻意的
[一句话结论 | 给 Vivienne]
──────────────────────────── sticky:压缩价格 + 裁决 + 5 个标签
```

- **裁决卡是全页唯一的大字号**,颜色即结论 —— 层级靠尺寸和色彩编码,不靠标题文字。
- **交易计划只留能直接下单的六个数**(入场/止损/目标/盈亏比/仓位/敞口上限);
  观望日换成「⏳ 在等什么」的第一条扳机。推理、波动档、QBTS 价位、杠杆换算
  全在「今日决策」标签里的**📋 计划细节**。
- **失效条件与一句话结论都夹行**(`line-clamp`),点开看全文 —— 它们各自能长到
  十几行,不夹就把首屏预算吃光。
  ⚠️ 夹行元素**不能同时加 `block`**:`line-clamp` 靠 `display:-webkit-box` 生效,
  `block` 会静默覆盖掉它(实测踩过)。

  都能直落那一页;`today` 不写 hash。
- 需要注意的标签打红点:事件(地缘 alert 或 high 催化剂)、系统(数据源异常)。

### 🌡️ 超买/超卖状态板(2026-07-30 用户点单)

用户:"为什么不显示当前的超买还是超卖,感觉很有用啊"。**查下来是算了但没露过面** ——
读数散在五处,而且都以"距扳机多远"的形式出现,没人回答"现在贵还是便宜"这句话本身:

| 读数 | 原本在哪 | 原本露不露面 |
|---|---|---|
| WaveTrend 日线 | `wavetrend.py` | ❌ 只有 **15m** 那份进 UI,还埋在 SMC playbook 清单第 ⑤ 项 |
| 特调 快/慢%R | `tiaojiu.py` | ⚠️ 进「今天在等什么」,但框架是距触发多远 |
| RSI2 | `waiting_for.py` | ⚠️ 同上 |
| RSI14 | `strategies.py`(VIX contrarian 用) | ❌ 决策页从不打印 |
| NW 包络位置 | `nadaraya_watson.py` | ❌ 只画成 60 日小图的带子,无文字读数 |

当初只留扳机、省掉状态**是有档案依据的**([../mining.md](../mining.md)):「经典指标当
独立系统」9 套在场胜率 47–54%(硬币)全部判死,活着的只有**具体的深度超卖扳机**
(RSI2<10 且站上 200 日线 n=40 后5天 +9.2%;特调 %R +17.4%)。不给通用超买超卖表,
是为了不诱发"RSI 30 = 该买了"那种已判死的推理 —— 但代价就是用户的这个感受。

**落地**:`backend/dashboard/oscillators.py` → `snapshot['oscillators']`;
前端 `_components/oscillator-board.tsx` 两个出口 —— 驾驶舱一行 `OscillatorStrip`
(贴价格轨下面,因为它回答的就是"这个价贵还是便宜")+「结构」标签整卡
`OscillatorBoard`(七行逐项)。

**三条不许破的线**:
1. **零决策权** —— 不进 `edge`、不进打分、不驱动 playbook、不发 ntfy,
   **也不进决策 prompt**:这些读数已经通过 waiting_for / NW / SMC 三条路进过
   prompt 了,再喂一遍就是把同一份证据当独立证据数两次(mining 第二十四轮原话)。
2. **不发明复合分数** —— 只并排陈列各振荡器**自己的**读数和**自己的**阈值,再数个数
   (几项超卖/几项偏冷)。一个合成的 0–100「超卖分」看起来就是信号,而它没有任何前向验证。
3. **单一数据源** —— RSI2 复用 `waiting_for._rsi` 同一实现,NW / SMC 区间位置直接从
   快照字段读回,绝不重算。同一个数在两张卡上显示成两个值是本仓库的老病。

**呈现**:一根轴全表共用(左=便宜/超卖,右=贵/超买),各行原生阈值画成刻度线。
配色是 diverging(emerald `#059669` ↔ `#F03A3E` + 中性灰),**跑过色觉校验**
(浅色底六项全过:正常视觉 ΔE 32.5 / deutan 9.6);**颜色永不单独承载信息** ——
每行都带文字档位与原生数值,并附「不依赖颜色的表格版」。
⚠️ 后端**不许往用户可见字符串里写 markdown**:前端渲染纯文本,`**粗体**` 会原样
印出来(第一版踩了,已改成拆字段 `caveat_cn` 交前端上样式)。

### 重排的两条纪律

1. **只搬运,不改写区块内部实现** —— 那些卡片里埋着几十条修过的 bug,重排时
   动它们等于把已修的坑再踩一遍。搬完用「字段访问指纹」对比新旧文件确认
   **零丢失**(`snap.*/d.*/live.*` 全集一个不少)。
2. **同一个数不许在两处显示成两个样**。sticky 条和价格轨的涨跌幅统一 2 位小数,
   价格/徽章全走同一个 `liveCurrent` 口径 —— 否则又是 cross-source 矛盾那类老病。

## 🔬 第二考场 `/mu`(`second_ticker.py`)—— 2026-07-30 用户点单

**这是测量轨,不是第二个交易页。** 存在的理由是 REVIEW-2026-07 §5 的算术:判决主体
(方向表态)每个交易日只 +1 个样本 → 9 月初才够 n=30,而**一个考场的结论永远可能是
运气**。加一只与 QBTS 低相关的票 = 样本速度翻倍 + 两场独立考试。

**选票过程(用户问"什么票值得盯",实测 20 个候选)**:先按「与 QBTS 相关性 + 跳空
频率 + 3 日波幅 + 流动性」排序,并**逐个用真实成交量验证 2× 杠杆 ETF 是否存在**。
直接排除同族:IONQ **0.81** / RGTI **0.88** / OKLO 0.65 / ASTS 0.55(同一个赌注
下两遍;ASTS 跳空还比 QBTS 更频繁)。选中 **MU**:相关 +0.28、MUU 日均 $2.7B(最厚)、
有真财报 → 财报/宏观/板块/「QQQ vs 50 日线」这几个模块**第一次有意义**
(它们装在营收为 0、对宏观免疫的 QBTS 上一直是摆设)。

⚠️ **选票理由里有一条当天就被自己推翻,已写进代码与 payload,不许悄悄删**:
原说"跳空少 → 盲区小",但按近 60 日窗口 MU 跳空 ≥8% 的频率 **6.7% = QBTS(3.3%)
的两倍**,年化波动 77%→114%。第二十八轮那个盲区在 MU 身上**更严重**。保留 MU 的
理由只剩「低相关 + 真财报 + 工具厚」—— 对"测方向"仍然充分(波动大只影响每笔盈亏,
不影响能不能测)。要零盲区就换 NVDA(跳空 0.0%、相关 +0.18),`_TICKERS` 加一行即可。

### 六条纪律(改 `second_ticker.py` 前必读,模块 docstring 里有完整版)

1. **只表态,不给动作** —— 无 entry/stop/target、无仓位建议、无 ntfy。表态可以说
   down,因为**没有任何东西会执行它**;绝不能拿"换了票没测过"当开空腿的后门。
2. **绝不写 `decision_journal`** —— 自己一张 `second_journal` 表,id = `<票>-<日期>`。
3. **零决策权于 QBTS** —— 不进 QBTS 的 snapshot/prompt/edge。两个考场互相看答案就
   不独立了。
4. **同一个考场标准** —— 同一个模型(借 `decision._MODEL` + 同一 fallback)、同一
   `bold_call` 语义、**直接复用 `journal._horizon_grades`**、同一条预注册线
   `audit._HORIZON_RULE`。换标准 = 换考试。
5. **判决分池** —— 不与 QBTS 合并成一个大 n(同一天两票的表态不独立,合并虚增样本)。
6. **成本可见** —— 每票每天 1 次 LLM 调用(加票 = 一行配置 + 约 $0.1/天)。

### 落地细节
- 简报**不新写任何指标**:复用 `analyze_smc` / `analyze_regime` / `analyze_nw_envelope`
  / `analyze_wavetrend` / `analyze_volume_profile` / `scan_ticker` / `detect_event_day`
  (它们本来就只吃 DataFrame,与票无关)。
- `run_daily()` **先 grade 再 record** —— 反了的话今天刚写的记录会被立刻空评一遍。
- `_save()` **返回是否真写成功**;失败时 `record()` 返回 None。否则表还没建时页面会
  显示一个没落库的表态、第二天凭空消失 = 假账本。
- 范围 clamp 在 `generate_lean` **和** `record` 两处都做:结构化输出 schema 不支持
  `minimum/maximum`(API 直接 400),代码是唯一防线,而 `lean` 可由调用方传入绕过。
- ⚠️ 需在 Supabase 跑 `sql/second_journal_migration.sql`(按仓库惯例迁移不入 git)。

卖在**入场时固定的波动缩放止损**(≈2× 日波动,夹 6–14%,`_stop_pct`)/ 偏空回避 / 到目标,
0.2%/边。

- **2026-07-01 fix**:老版模拟器把 UI 的软提示"跌破20/50线"(`exit_hint`)当硬止损,
  于是一个买入区(要求 close>20MA,但可以在 50MA 下方)开仓当天就被判 'risk' 止损 →
  每笔都是 1 天洗盘亏损。现在止损是自己的、锚在入场价的水平,且入场要过大盘门;
  账本因此重置过一次。
- **2026-07-13 机制 v2**(首月战绩买入区 0/6、账本 −$226 后六连修):①目标过 **1.5R 盈亏比门**

  ②模拟器改 **回踩限价挂单**(照卡片打法挂需求区上沿,5 交易日内触价按 min(open,limit) 成交,
  过期/转空撤单;现价已在买点才即时进场)③买入区改 **顺风×回踩合取**(pts≥3 且 趋势腿 且
  位置腿,缺腿降级)④**板块轮动门**(`SECTOR_OF` 映射到 sector_rotation 象限,左半边降级)
  ⑤无目标仓位 **破 10 日线跟踪出场** ⑥`avoid` 避雷块(偏空回避 = 首月唯一 66% 命中的信号)。
  新单 `epoch='v2'`,v1 老仓按新出场规则跑完,**审判按 epoch 分开统计**;前端 v1 折叠归档。

## 📥 定投专区(`dca.py`)

2026-06-24 重建为全球**估值菜单**:**VTI / VEA / VWO / AVUV**(**故意不是** VOO/QQQ/VTI/IOO

接近高点买入没问题。卡片显示 P/E + 盈利收益率(CAPE 代理)+「与 QBTS 投机仓分开」的警告。
宏观 CAPE(美 ~40 / 全球 ~27.7)是硬编码的,带"需复核"注。

**2026-07-13(用户:"都加")补全为完整组合**:股票档 **+AVDV**(国际小盘价值,AVUV 的镜像),
权重 30/20/14/8/8 = 80%;加**压舱石档**(`BALLAST_META`)**BND 12% + GLDM 8%**,自己的卡片+权重
(`ballast_etfs` in payload)→ 合计 100%。**压舱石的投放规则被覆盖为「固定比例·不择时」**——

## 🏆 策略战绩 `/factors`(`replay.py`)

七匹纸面马 + 观察组 + 游击战账本的全历史复算(买卖点/收益/当前状态)。
观察组卡:CPI+PPI 公布日 / 周一BTC大绿日内 / GPR 地缘缓和 / `obs_levmr` 杠杆ETF超卖回归 /
`obs_lockflip` 锁翻多×QBTX×3天 —— **不进决策不算在册**,8/15 凭记录 + 各自预注册标准复查升马。
纸面马报同窗口 buy&hold 对照(`bh_ret_pct`)—— 否则"全是亏损"的观感会掩盖它们其实全都跑赢 B&H 4–11pp。
